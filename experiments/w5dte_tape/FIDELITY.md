# FIDELITY -- W5DTE forward paper tape proxy calibration

Generated by `calibrate_proxy.py`. Archive scan: 8.0s, 381/382 anchor day(s) processed (stride=1), 10025997 calibration row(s).

## What this calibrates

The w5dte_ev rule family's discovered conjunct is `hl_range_pct >= P80(127.3)` (intraday high-low range as a percent of close, RESULTS_TABLES.md E3) -- but the live production source for the forward paper tape, `option_prices`, is a daily lastPrice/volume/OI SNAPSHOT with no intraday high/low. The tape substitutes a LIVE-OBSERVABLE proxy: the close-to-close move between a contract's two most recent daily snapshots, `proxy_move = |price_t/price_{t-1} - 1|`. This script measures, on the archive (which HAS true intraday high/low), how well that proxy stands in for the true conjunct.

## Methodology

- Substrate: `B:\polygon_derived\contract_day_index\_bydate\*.parquet` (FF-0), sessions enumerated via `ff_common.list_session_dates('day_aggs_v1')` (the archive's own filesystem-walk calendar -- never a directory glob).
- Window: <= 2026-06-12 (971 in-scope sessions, 382 of them Monday/Tuesday). Holdout-safe: this is the SAME window the parent weekly_5dte_movers study and w5dte_ev already used; `experiments._holdout.assert_no_holdout_leak` asserted no date beyond it was touched.
- Anchor days = every Monday/Tuesday session in-window (stride=1; stride=1 means ALL 382 were used -- a 6-file throughput probe measured ~10 files/sec, so the full population finished in 8.0s, well inside the ~10 min budget and no subsampling was actually needed; `--stride N` remains available for a slower box).
- For each anchor day `d`: loaded `d`'s own `_bydate` parquet (ticker, cp, close, high, low, volume) and the TRUE immediately-prior trading session `d-1`'s parquet (ticker, close only) -- `d-1` comes from the FULL archive calendar, not a subsampled one, so the day-gap matches what the live tape's own 'most recent prior OptionPrice row within 5 days' lookup actually sees in production (almost always exactly 1 trading day).
- Population = contracts present on both `d` and `d-1`, filtered to 'Mon/Tue tradeable-ish': close_d >= $0.20, volume_d >= 100 (this task's own floor -- looser than the parent study's full tradeable floor, which also requires transactions>=10; not applied here).
- `hl_range_pct = (high_d - low_d) / close_d * 100` (the true conjunct); `proxy_move = |close_d / close_{d-1} - 1|` (the live-observable proxy).
- True threshold used verbatim from RESULTS_TABLES.md E3: `hl_range_pct >= 127.3` (the task's own pinned value -- a rounded P80 display label, same status as the parent's other rounded rule labels; not re-derived to full precision here since this calibration is on a structurally different population than E3's rule-distillation grid).
- **No sector or moneyness restriction** -- calibration is unconditional over the WHOLE archive (all underlyings, both sides). This script is read-only over B: parquets with NO MySQL access (as directed), so a technology-sector restriction (which needs `stocks.sector`, a MySQL-only field) is not possible here. The live entry rule restricts to technology/calls; this calibration's fidelity numbers are therefore ASSUMED representative within that subset, not independently confirmed for it -- flagged as an open question in TAPE_BUILD_REPORT.md.

## Calls only (cp=='C') -- THE VALUE w5dte_tape.py USES LIVE

N = 5870587

### (a) Proxy threshold X matched to the true-conjunct exceedance rate

- True conjunct: `hl_range_pct >= 127.3`  -->  rate = 5.159% of the population
- **X = 1.000000**  (proxy_move exceedance-rate-matched threshold: `proxy_move >= X` fires at rate 5.245%, matched by construction to the true rate above)

### (b) Confusion matrix / agreement rate at X

| | true hit (hl>=127.3) | true miss |
| --- | --- | --- |
| proxy hit (proxy>=X) | TP=19979 | FP=287952 |
| proxy miss | FN=282901 | TN=5279755 |

Agreement rate (TP+TN)/N = **90.276%**
Recall (TP / true hits) = 6.596%
Precision (TP / proxy hits) = 6.488%

### (c) Spearman rank correlation

rho(proxy_move, hl_range_pct) = **0.5623**

### Interpretation

The hard threshold is a WEAK screen at the individual-contract level: precision/recall are only ~7% despite a moderate positive rank correlation (rho=0.56). Concretely: most contracts that clear `proxy_move >= X` would NOT have cleared the true `hl_range_pct >= 127.3` gate that day, and most contracts that WOULD have cleared the true gate are missed by the proxy. The agreement rate (90.276%) is even slightly BELOW the trivial 'always predict miss' baseline (94.841%), which is expected under this much class imbalance (~5.2% positive rate) and should not be read as 'agreement is good' on its own -- rho and the confusion matrix are the more honest read. Interpretation: `proxy_move` is DIRECTIONALLY informative (a bigger close-to-close move does mean a bigger true intraday range, on average) but is a noisy, not crisp, stand-in for the true violence conjunct at any single hard cutoff. The paper tape's entry rule uses it as a hard gate anyway (per spec) -- this is exactly the deviation FINDINGS.md's Disposition means by 'every deviation is quantified; the tape is disposable if the owner rejects the proxy.'

## Which X the live tape uses

`w5dte_tape.py` reads `calibration_stats.json`'s `recommended_X`, which is set to the **calls-only** value (X=1.000000), not the pooled one (X=0.887500). The live `--entry` rule only ever evaluates calls (technology-sector, calls-only design decision -- see TAPE_BUILD_REPORT.md), so the threshold is calibrated on exactly the population it is applied to rather than diluted by puts the tape never touches. N=5.87M for calls-only is still a very large, statistically robust sample -- there is no power cost to this choice, only a scope correction. The pooled and puts-only numbers above are reported for completeness and as a robustness cross-check (rho and agreement are similar across all three slices), not because either feeds the live gate.

## Standing caveats (carried from experiments/w5dte_ev/FINDINGS.md "Disposition")

- **Outcome proxy = lower bound.** The `--outcomes` mode of w5dte_tape.py prices the week's outcome off `max(subsequent daily option_prices.price)`, which is a LOWER bound on the true week high (`max_future_high` in the parent study's ledger) -- a daily lastPrice snapshot can miss an intraday spike the true high captured. This calibration is about the ENTRY-side violence conjunct only; it does not measure or correct the separate outcome-side lower-bound gap.
- **Volume is unreliable live.** `option_prices.volume` (yfinance-sourced) reads 0 on a large majority of rows even for deeply liquid contracts -- .horizon/ct15-paper-sleeve/LESSONS.md measured 79% zero-volume on a 2000-row sample, and a specific liquid AAPL contract read volume=0 on all 21 sampled days despite genuinely moving day to day. This is why w5dte_tape.py's `--entry` mode LOGS volume/open_interest but never gates on them.
- **The archive is dead.** `B:\polygon_flatfiles\us_options_opra\` stopped receiving new sessions 2026-08-05 (Polygon entitlement lapsed, data-acquisition.md). This calibration is therefore a ONE-SHOT: it cannot be re-run against fresher archive data if the live proxy's fidelity ever needs re-checking -- X is fixed at the value computed here unless a future session re-derives it from a different archive source entirely.
